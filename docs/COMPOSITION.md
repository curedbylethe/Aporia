# Composition

- Sort the content into primary task or conclusion, supporting information, and lookup material. Use the same order in the document and keyboard path.
- Establish a left alignment shared by the main heading, body and most evidence. Use a side column for metadata, controls or comparison only when it can be scanned independently.
- Use asymmetric widths when the content has asymmetric importance. For a 12-column publication, a wide argument and a narrow notes column are a useful starting point.
- Let a rule or whitespace close a topic. Use the smaller spacing steps inside a group and larger steps between independent groups.
- Keep prose near 62ch, single-line labels short and data columns wide enough for real values. Break long paths safely and give long code lines their own scrolling region.
- In a narrow view, stack in DOM order. Keep a toolbar above the result it affects and place a selected row's evidence directly after the result list.
- Test a grayscale screenshot and a 200% zoom view. Look for a recognizable entry point, intact reading order and stable alignment.

The [dossier](../references/editorial/dossier/) pairs an opening thesis with metadata and evidence. The [dashboard](../references/interface/dense-dashboard/) uses aligned rows because comparison is the primary task.
